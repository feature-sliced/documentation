# Группы слайсов

Группа слайсов позволяет расположить связанные слайсы рядом в пределах одного слоя, чтобы в структуре проекта было проще ориентироваться.

Группы слайсов не обязательны в FSD. Их можно вводить по мере необходимости, когда слайсов становится настолько много, что в плоской структуре трудно ориентироваться.

## Общие сведения

Группа слайсов нужна для удобства чтения кода и навигации. Она не влияет на правила зависимостей между слайсами.

Группа слайсов сама по себе не является слайсом. У неё нет собственных сегментов, таких как `model`, `ui` или `api`, и публичного API, например `index.ts`. Общий код, который используют несколько слайсов, тоже нельзя размещать в папке группы.

Каждый слайс остаётся независимым, даже если входит в группу. Правила изоляции и зависимостей между слайсами не меняются.

## Зачем нужны группы слайсов

Когда слайсов становится много, в плоской структуре бывает трудно найти связанный код. Если слайсы с общим контекстом разбросаны по слою, приходится несколько раз просматривать весь слой.

Группа слайсов решает эту проблему: связанные слайсы располагаются рядом, и в структуре становится проще ориентироваться.

## Когда стоит создать группу

Подумайте о создании группы слайсов, если критерий группировки очевиден с первого взгляда, а разделение структуры действительно делает её понятнее.

- Несколько слайсов с общим бизнес-контекстом разбросаны по слою.
- По названиям слайсов ясно, что они относятся к одной теме.
- Слайсов в слое стало настолько много, что структуру трудно охватить одним взглядом.

В следующих случаях группа, скорее всего, пока не нужна.

- Названий слайсов достаточно для быстрой навигации.
- Нет естественного критерия группировки.
- В группе окажется слишком мало слайсов.

## Как использовать группы слайсов

### entities

Можно группировать слайсы, близкие с точки зрения модели предметной области.

Допустим, в слое `entities` накопилось много слайсов, связанных с платежами.

**Без группы:**

- entities/
  - invoice/
    - model/
    - ui/
  - receipt/
    - model/
    - ui/
  - transaction/
    - model/
    - ui/
  - user/
    - model/
    - ui/
  - product/
    - model/
    - ui/
  - ...
Чтобы найти слайсы, связанные с платежами (`invoice`, `receipt`, `transaction`), придётся просмотреть весь слой и выбрать их по одному.

**С группой:**

- entities/
  - payment/
    - invoice/
      - model/
      - ui/
    - receipt/
      - model/
      - ui/
    - transaction/
      - model/
      - ui/
  - user/
    - model/
    - ui/
  - product/
    - model/
    - ui/
  - ...
Теперь все слайсы, связанные с платежами, можно найти прямо в `payment/`.

Не каждый слайс должен входить в группу. Например, слайс `user/`, назначение которого понятно само по себе, можно оставить вне групп.

### pages

Аналогичным образом можно группировать связанные страницы в слое `pages`. Ниже приведён один из возможных примеров, а не стандартная структура этого слоя.

- pages/
  - order/
    - create/
      - ui/
    - detail/
      - ui/
    - list/
      - ui/
  - customer/
    - detail/
      - ui/
    - list/
      - ui/
  - settings/
    - ui/
  - ...
Такая структура полезна, когда есть несколько страниц на одну тему: например, страницы списка, подробной информации, создания и редактирования.

### Можно ли использовать группы в features?

Да, группы слайсов можно использовать и в слое `features`. Однако фича часто затрагивает несколько сущностей, а не связана с одной предметной областью. Поэтому здесь сложнее найти естественный критерий группировки, чем в `entities`.

Если создать группу вроде `features/cart/` без чёткого критерия, в неё попадут сценарии использования `add-to-cart` и `remove-from-cart`. При этом там могут начать накапливаться DTO и мапперы, связанные с корзиной. Тогда папка группы перестанет служить только для навигации и превратится в место для всей предметной области корзины. Это ослабит принцип разделения фич по сценариям использования.

Прежде чем создавать группу слайсов в `features`, проверьте, достаточно ли слайсов, чтобы группировка имела смысл. Если их всего два или три, плоской структуры, скорее всего, хватит. Также убедитесь, что группа содержит только слайсы фич, а не код, которому место в `entities`.
